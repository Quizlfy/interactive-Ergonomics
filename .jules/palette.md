## 2024-04-25 - Interactive Divs Need Explicit A11y Attributes
**Learning:** In simple static HTML presentations, clickable interactive `div` elements (like `.card` or `.burger`) often rely solely on `onclick` handlers. This causes major accessibility regressions: they are unreachable by keyboard (no `tabindex`), have no focus state for keyboard users, and are invisible as interactive components to screen readers (missing `role="button"` and `aria-expanded`).
**Action:** When auditing or implementing interactive `div` or `span` components, always add `role="button"`, `tabindex="0"`, a keyboard event listener (`onkeydown` checking for Enter/Space), and `:focus-visible` styles to ensure full parity with native `<button>` elements.
## 2024-06-08 - Hide Decorative Emojis and Initials from Screen Readers
**Learning:** Decorative icons (like emojis in `<div class="icon">`) and dynamically generated initial avatars (`<div class="avatar">`) next to full names can cause redundant and confusing screen reader announcements. Screen readers may read the raw emoji descriptions or the isolated letters of the initials, which provides no additional value to the user since the adjacent content already conveys the meaning.
**Action:** When adding purely decorative visual elements (like emojis) or visual companions to textual data (like avatar initials next to full names), always apply `aria-hidden="true"` to prevent redundant or noisy screen reader announcements.
